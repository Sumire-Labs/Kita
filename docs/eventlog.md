# EventLog

EventLogはサーバーの操作をComponents V2で記録します。追加のスラッシュコマンドはありません。
初期状態では無効です。`/settings` → EventLogで共通出力先を選び、有効にしてください。
設定操作には毎回サーバー管理権限が必要です。パネルは開いた本人だけが操作できます。

## 記録対象

| カテゴリ | 操作 |
| --- | --- |
| MESSAGES | 編集、削除、一括削除。添付変更を含む |
| MEMBERS | 参加、退出、ニックネーム、ロール付与・解除 |
| MODERATION | Kick、Ban、Unban、タイムアウト変更 |
| VOICE | 参加、退出、移動、管理者による移動・切断・ミュート変更 |
| ROLES | 作成、変更、削除 |
| CHANNELS | 作成、変更、削除、権限変更 |
| SERVER | サーバー設定変更 |

VCの自己ミュート・スピーカーミュート・配信・カメラ変更は初期状態で無効です。
共通出力先に加え、カテゴリ別の出力先を指定できます。個別指定を解除すると共通先を使います。
出力先は通常のテキストチャンネルです。ログ出力先とそのスレッドは記録対象から除外します。
Kita自身は常に除外し、他のBot・Webhookの操作も初期状態で除外します。
除外チャンネル・カテゴリは最大25件、除外ユーザーも最大25件です。
VC移動は移動元・移動先のどちらかが除外対象なら出力しません。
本文を含むログは元チャンネルの閲覧者以外にも見えるため、出力先の閲覧権限を設定してください。
初期値はサイレント送信で、通常通知へ変更してもユーザー・ロール・everyoneへの通知は行いません。

## 必要なDiscord設定

- Message Content Intent：編集・削除前の本文の受信に必要です。
- Server Members Intent：参加・退出に必要です。Developer Portalで有効にしてBotを再起動してください。
- 監査ログを表示：ロール・チャンネル・サーバー設定、ニックネーム・ロール変更、管理操作に必要です。
- 出力先でチャンネルを見る・メッセージを送信・ファイルを添付：出力先の設定時と送信時に検証します。

起動時にアプリケーション情報でMembers Intentの使用可否を確認し、許可された場合だけ要求します。
設定画面には現在のMembers Intentと監査ログ権限の状態を表示します。
Members Intentを要求しても、全メンバーの一括取得は行いません。

## 保存期間と容量

有効化後に受信した対象チャンネルの本文をMariaDBへ保存します。過去の履歴を収集しません。
初期値は6時間・サーバーごと64MiBです。期間は1／6／24時間、容量は8／32／64／128MiBから選択できます。
編集時は最新内容の受信から保存期間を数え直します。期限切れの本文は読み出さず、約1分間隔で削除します。
添付はファイル名・URL・サイズ・IDだけを保存し、画像やファイル本体をダウンロードしません。
Bot・除外ユーザーには本文を保存せず、削除時の除外判定用にIDなどの短期メタデータだけを保持します。
「本文・添付情報」を無効にすると、本文を保存・送信しません。
設定変更やサーバーからの退出で、そのサーバーの保存本文と送信待ちログを削除します。
設定変更時、既にDiscordへ送信中のリクエストまで確実に取り消すことはできません。

全体の保存枠は論理データで本文2GiB、送信待ち128MiBです。
16個の枠に分割するため、偏りによって全体上限より前に古い保存本文が削除される場合があります。
送信待ちはサーバーごと最大8MiB。取り込み待ちは全体最大512件で、上限到達はBotログへ記録します。
DBのインデックス・ログ・ページの余裕分は含まないため、実際のディスク使用量はこれらの値を超えます。
送信待ちログにも選択した保存期間を適用します。送信成功後は本文を消し、重複防止用IDだけ期限まで残します。
Discordの出力先へ送信済みのログや、運用者が取得したDBバックアップは自動削除の対象外です。
V5マイグレーションはEventLog用テーブルを追加します。既存設定や他機能のデータは変更しません。

## 表示と制約

短い本文はログ内に、長い本文・一括削除の取得内容はUTF-8テキストファイルとして表示します。
本文未受信・期限切れ・容量制限・Bot停止中の操作など、取得できない内容はその旨を表示します。
一括削除では受信済み・保存対象の内容だけを添付します。最大100件・約256KiBまでです。
実行者は監査イベントの情報を使用します。メッセージ削除の実行者を監査ログの近さから推測しません。
退出イベント単体では自主退出・Kick・Banを断定しません。確認できた管理操作は別のログになります。
管理者によるVC操作も、Gatewayの移動ログと監査ログの両方が表示される場合があります。
監査情報に個別ユーザーや移動元が含まれない操作は、分かる範囲の件数・移動先を記録します。
監査イベントの機密項目を無差別に転記せず、名前・権限・対象設定など許可した項目だけを表示します。
連続編集はDiscord RESTで取得した最新内容にまとまる場合があります。完全な編集履歴は保証しません。
Bot/Webhookかどうか判別できる保存情報がない古い削除では、投稿者が不明なことを明示します。
Discord送信とDBの更新をまたぐクラッシュでは重複送信の可能性があります。

既存の`earthquake.*`設定キー、内部パッケージ、操作IDと`/quake`は維持し、再設定を不要にしています。

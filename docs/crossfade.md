# Music crossfade

`/settings → Music`でOFF・1〜12秒（1秒刻み）を選択します。初期値はOFF、おすすめは5秒です。
設定はGuild IDごとにMariaDBへ保存し、変更は次に開始する曲から適用します。
設定パネルは開いた本人だけが操作でき、毎回サーバー管理権限を再検証します。
プレイヤーの操作は従来通り同じVCへの参加と権限が必要です。

## 音声経路

Lavaplayerの2つのPCMプレイヤーで現在曲と次曲をデコードします。
48 kHz・ステレオPCMを等電力カーブで合成し、ピークにソフトリミットを適用します。
合成結果を既存のHRIRフィルター、音量、Opusエンコーダーへ渡します。
曲ごとにHRIRを重複適用したり、音源をOpusへ圧縮してから混ぜたりはしません。
曲間の音声タイミングは音声ノードのサンプル数で制御し、Botや15秒ごとの画面更新には依存しません。
画面とキューは500ms間隔で、実際に取り出された音声フレームの位置を確認します。
デコード先行分を「再生済み」と判定しないため、一時停止中にキューが先へ進みません。
画面では切り替え中の2曲を表示し、切り替え終了後に次曲へ進みます。
従来のプレイヤー更新間隔は15秒のため、画面更新の間に短い切り替えが終わる場合があります。

## 対象と操作

- 自然な曲終了から次のキュー曲へ進むときに適用します。取得元サービスに限定しません。
- ライブ・長さ不明・シーク不可の曲、40ms未満の曲は対象外です。
- 短い曲では現在曲・次曲の半分以下になるように重なる時間を短縮します。
- トラックループでは先読みしません。キューループは別の次曲があれば適用します。
- キューに1曲だけのループは通常の再開始になります。
- 切り替え開始後にトラックループを選んだ場合、進行中の切り替えは完了し、その次からループします。
- スキップ・前へ・停止・VC常駐終了は、現在の合成と先読みを終了します。
- 一時停止は出力全体を止め、再開時に同じ音声位置から続けます。
- 音量・HRIRプリセットの変更は合成後の音声経路へ適用します。
- クロスフェード中のシークは未対応です。現在のプレイヤー画面にシーク操作はありません。

## 失敗と上限

次曲は最大1曲だけ先読みします。最初の曲のPCMバッファは1秒、次曲は設定時間＋1秒（最大13秒）です。
次曲へ昇格後もそのバッファサイズを維持し、各プレイヤーのバッファは最大13秒に制限します。
通常は残り時間がクロスフェード時間＋20秒以内になった時点で次曲を準備します。
準備が遅れた場合は重なる時間を短縮し、準備できない場合は通常の曲切り替えになります。
重なり始めた後の一時的な音声不足では位置を保持して待機し、次曲を破棄・最初から再生し直しません。
次曲が終了した場合はその曲への移行を確定し、60秒間再開できない場合はエラーを表示します。
切り替え時刻には元の曲情報の長さを使い、デコーダーが返す不明な長さによる計算の誤りを防ぎます。
音声ノード1台につきクロスフェードは最大32セッション、PCMデコーダーの実行スレッドは最大64です。
これは安全上限で、Core i7-7700Kで32サーバーのHRIR再生を保証する値ではありません。
上限到達やプラグインが使えない場合は通常再生へ戻し、Botの運用ログへ記録します。
通常再生のサーバー数は、このクロスフェード上限とは別です。
3回連続して制御状態を取得できない場合は画面にエラーを表示し、再生・スキップで復旧します。
キュー・再生状態は従来同様プロセス内の状態です。Bot再起動で復元しません。
単一のencoded trackでは合成状態を復元できないため、音声ノードの途中移行・再起動後の自動復元は未対応です。

## 検証

生成した440Hz・880Hzの音源を実際のLavaplayerプレイヤーでデコードし、重なり区間の両周波数を検証します。
3秒＋3秒を1秒重ねると約5秒になり、HRIRありでも連続した経路になることを検証します。
一時停止・ピーク制御・キューの二重送り防止・古い制御応答・接続失敗をテストします。
`KITA_TEST_CROSSFADE_NODE`を指定したテストでは、生成WAVを配置した隔離Lavalinkへ実際のJavaクライアントで接続します。
実際のDiscord VCでの聴感、外部サービスの音源取得、実サーバー数での負荷は別途確認が必要です。
